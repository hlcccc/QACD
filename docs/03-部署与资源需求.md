# 部署与资源需求

## 1. 组件与依赖

| 组件 | 是否必需 | 说明 |
|---|---|---|
| QACD 决策层（本仓库 `qacd/`） | 必需 | 仅依赖 **NumPy**，CPU 可跑，无需 GPU |
| 冻结 LVLM（LLaVA-1.5-13B） | 必需 | 证据通道与分解调用；GPU 显存主要消耗方 |
| OCR 引擎（RapidOCR / ONNX Runtime） | 必需 | 机械仪器通道；CPU 即可 |
| MVR 采样能力 | 可选 | 需要 LVLM 支持同 prompt 多采样；K=3 为性价比拐点。**同时必须启用 OCR 通道**——见下方说明 |
| 开发集标签 | 必需 | **≥300 条**才能拟合出可用的校准器；换新领域建议 ≥1,200 条，见第 4 节 |

```bash
# 完整安装（包 + qacd 命令行入口 + 测试依赖）—— 推荐
pip install -e ".[test]"

# 或只装运行时依赖（numpy、pandas）。注意：这不会创建 `qacd` 命令，
# 也不会装 pytest；此时请用 `python -m qacd.cli` 代替 `qacd`。
pip install -r requirements.txt

# 服务模式
pip install -e ".[service]"     # 等价于 fastapi + uvicorn + pydantic

# OCR 通道
pip install -e ".[ocr]"         # 等价于 rapidocr-onnxruntime

# LVLM 证据提供方
pip install -e ".[llava,ocr]"   # 等价于 torch + transformers + accelerate + pillow
```

> ⚠️ **MVR 通道依赖 OCR**。`mvr_features` 判断每次重采样是否"有支持"，靠的是把采样文本
> 与从图像读出的文字做比对；没有 OCR 文本时没有任何东西可比，每一次采样都会被判为
> unsupported，7 个 MVR 特征全部恒定，融合头学不到东西（此时拟合会被拒绝并给出告警）。
> 也就是说 `--k > 0` 但没接 OCR，等于白付采样成本。用 `LLaVAProvider(ocr_provider=...)`
> 或在 CLI 上不要加 `--no-ocr`。

## 2. GPU 与显存

| 项 | 值 | 依据 |
|---|---|---|
| 主模型 | LLaVA-1.5-13B | 与论文冻结配置一致 |
| fp16 权重占用 | **实测 26.7 GB**（峰值 27.74 GB） | A100-SXM4-80GB 实机 `LLaVAProvider.load()` |
| 推荐单卡显存 | **≥ 40 GB**（A100-40G / A100-80G / A800 等） | 权重 + 证据探针批处理余量 |
| 研究期实测平台 | 2 × NVIDIA A100-SXM4-80GB，每卡一进程 | 服务器 `nvidia-smi` 核验 |
| 24 GB 卡 | 需 8-bit / 4-bit 量化或换 7B 主干 | 量化后精度需在有标注数据上另行标定 |

平台容量规划建议以**模型调用次数**作为主要成本代理（见下节），
时延与吞吐在联调阶段实测后写入容量基线。

## 3. 模型调用次数（成本代理）

| 配置 | 每回答模型调用次数 |
|---|---:|
| 1 视图 + MVR K=2 | 6.61 |
| 1 视图 + MVR K=3 | 7.61 |
| 1 视图 + MVR K=5 | 9.61 |
| 4 视图 + MVR K=2 | 9.61 |
| 4 视图 + MVR K=3 | 10.61 |
| 4 视图 + MVR K=5 | 12.61 |
| LM 通道本身（不含重采样） | 7.65 |
| MVR 每增加 1 层采样 | +1 |

**视图数从 4 降到 1 对精度几乎无损**（实测无可辨差异），
但调用次数从 12.61 降到 9.61（K=5 时 **−24%**）。平台若受算力约束，
**优先降视图数而不是降 K**。

## 4. 开发集规模需求

冻结测试集上的固定留出学习曲线（开发集规模 → AUROC）：

| 开发回答数 | QACD AUROC | Claim BCM AUROC |
|---:|---:|---:|
| 301 | 0.7777 | ~0.754 |
| 800 | 0.7890 | ~0.754 |
| 1,200 | 0.7942 | ~0.754 |
| 3,000（全量） | 0.7978 | ~0.757 |

- **300 条是下限，不是够用线**：该规模尚未饱和。
- 增益的大部分在约 **1,200 条**时已实现，之后仍有小幅剩余增益。
- 因此：300 条可以拟合出能跑的打分器；要冻结一个**可交付**的打分器，建议 ≥1,200 条带标签回答。

## 5. 存储

研究期产生的中间产物规模（2026-09 核验，供工作量预估参考）。
下表只列目录名，绝对路径已省略：

| 目录 | 占用 | 内容 |
|---|---:|---|
| `cache/` | 2.7 G | 生成/特征缓存 |
| `backups/` | 3.5 G | 重写前备份 |
| `vizwiz_20260921/` | 3.7 G | VizWiz 数据与产物 |
| `ocr_env/` | 918 M | OCR 虚拟环境 |
| `qacd_conditioning_fix/` | 170 M | 条件化修复重跑 |
| `qacd_revision_20260915/` | 103 M | 早期主结果 |
| 其余 `qacd_*` 结果目录 | 各 0.2–5 M | 指标 CSV 与图 |

**平台容量规划要点**：

- 数据集原始图像与模型权重为 **GB 级**，必须落在大容量数据分区，不要放在系统盘。
- 虚拟环境、包缓存、临时目录与训练/推理输出都要**显式**指向该分区。
  实测教训：把缓存留在系统盘会迅速耗尽根分区（本次研究期根分区一度只剩约 5% 可用空间）。
- 单个 `qacd_*` 结果目录很小（MB 级），真正占空间的是缓存、环境与数据集。

## 6. 部署步骤

```bash
# 1. 取代码
git clone <repo-url> && cd QACD

# 2. 安装（包本体 + qacd 命令行入口 + 测试依赖）
pip install -e ".[test]"

# 3. 自测（不需要 GPU、不需要模型权重）
python -m pytest -q                 # 210 项测试（195 通过 + 15 跳过）
python scripts/demo_offline.py      # 端到端离线演示（合成开发集）

# 4. 准备真实证据环境
pip install -e ".[llava,ocr]"
#   冻结的 LLaVA-1.5-13B 检查点（fp16 约 26 GB，建议 ≥40 GB 显卡）
huggingface-cli download llava-hf/llava-1.5-13b-hf --local-dir /models/llava-1.5-13b-hf

# 5. 用平台自己的开发集拟合打分器（必须显式指定 --provider）
#    dev.jsonl 每行：{"question":..., "answer":..., "image":..., "failed":0|1, "group":...}
qacd fit --data dev.jsonl --out scorer.json --k 3 \
         --provider llava --model-path /models/llava-1.5-13b-hf

# 6. 起服务（provider 默认沿用打分器文件里记录的那个）
qacd serve --scorer scorer.json --host 0.0.0.0 --port 8080 \
           --provider llava --model-path /models/llava-1.5-13b-hf

# 7. 冒烟
curl -s localhost:8080/health
curl -s -X POST localhost:8080/v1/qacd/risk \
  -H 'Content-Type: application/json' \
  -d '{"question":"What brand is the camera?","answer":"Dakota digital","image":"demo.jpg"}'
```

**关于 `--provider`（必读）**：`score` 与 `fit` **必须**显式指定证据来源。

| 取值 | 含义 | 用途 |
|---|---|---|
| `llava` | 真实 LLaVA 检查点 + RapidOCR | **唯一能产出有意义分数的配置** |
| `mock` | 无模型、无图像，读数由词面重叠推得 | 只用于打通链路与接口自测 |

`--provider mock` 会打印醒目横幅，生成的打分器文件里也会记下
`provenance.provider_kind = "mock"`、`carries_model_evidence = false`，之后每次加载它
都会带出"该打分器不含模型证据、分数无意义"的告警。**不要把 mock 打分器接进业务库。**

一页可复制的完整真实流程见 `examples/run_real_provider.py`：

```bash
python examples/run_real_provider.py fit \
    --data dev.jsonl --model-path /models/llava-1.5-13b-hf --out scorer.json --k 3
python examples/run_real_provider.py score \
    --model-path /models/llava-1.5-13b-hf --scorer scorer.json \
    --question "what is the website that host this photo?" \
    --answer "Flickr" --image /data/textvqa/val/eb38600d8a5ade9a.jpg
```

**注意特征维度**：`qacd fit` 拟合的是 **48 维参考特征**（实时路径）。冻结报告数值所在的
**112 维冻结特征集**需要 `FrozenFeatureAssembler` 与冻结证据表，见
`docs/01-方法说明.md` 与 README「两条打分路径」一节。两者不可混用。
