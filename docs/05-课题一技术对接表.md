## 补充说明（协助平台建设排期用）

### 一、四个可独立对接的能力面

本技术点是**一个**交付项，内部包含四个可以分开接入的能力面。这样分是为了让平台按
"先易后难"的顺序落地，而不是说它们是四个独立技术点。

| 能力面 | 接口 | 是否可纳入平台建设 | 说明 |
|---|---|---|---|
| QACD 核心打分器 | `POST /v1/qacd/risk` | 可以 | 接口已定义；需接入平台 LVLM 与带标签开发集后产出打分器 |
| MVR 多视图重采样通道 | `POST /v1/qacd/mvr` | 可以 | 依赖同一 LVLM 的多次采样能力 |
| 机械 OCR 仪器通道 | `POST /v1/qacd/mechanical` | 可以 | 无 GPU 依赖，可独立验证 |
| 保形选择性预测与弃权 | `POST /v1/qacd/select` | 可以 | 纯 CPU 计算，工作点在平台自有校准批次上标定 |

### 三、资源需求与工作量预估

- **显存**：被评估模型 LLaVA-1.5-13B 在 fp16 下约 26 GB，建议单卡 ≥40 GB（A100-40G/80G 等）。
  24 GB 卡可考虑 8-bit/4-bit 量化或改用 7B 主干。
- **决策层**：仅依赖 NumPy，CPU 可运行，无 GPU 需求。
- **模型调用次数**（算力成本代理，完整表见 `docs/03-部署与资源需求.md` 第 3 节）：
  LM 通道本身 7.65 次/回答；4 视图 + MVR K=5 为 12.61 次。
- **成本优化**：视图数由 4 降至 1，实测精度无可辨差异，
  调用次数由 12.61 降至 9.61（K=5 时减少 24%）。受算力约束时优先降视图数，不要降 K。
- **开发集规模**：学习曲线显示 300 条尚未饱和，增益大部分在约 1,200 条时已实现。
  平台接入新领域建议准备 ≥1,200 条带标签回答再冻结打分器。

### 四、平台侧必须拦截的两种情况

| 情况 | 判别方式 | 平台动作 |
|---|---|---|
| 打分器未拟合 | `GET /health` 返回 `scorer_fitted: false`，或响应 `warnings` 含 `scorer is not fitted` | 拒绝将 `risk_score` 写入业务库 |
| 特征维度不匹配 | 响应 `feature_dim` 与平台记录不一致 | 拒绝并告警（表示打分器版本变更） |

### 五、建议的集成顺序

1. 先接 **机械 OCR 仪器通道**——无 GPU 依赖、可独立验证、最容易打通链路。
2. 再接 **QACD 核心打分器**——需要 LVLM 运行环境与平台自有开发集。
3. 然后加 **MVR 通道**作为精度增量，K 从 3 起调。
4. 最后接 **保形弃权**，在平台自有校准批次上标定工作点。
